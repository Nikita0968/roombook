# RoomBook — Система бронирования учебных аудиторий

**RoomBook** — это веб-приложение для студентов и преподавателей, предназначенное для бронирования учебных аудиторий на конкретную дату и время. Система позволяет создавать заявки, проверять занятость аудиторий, отслеживать статус бронирования и управлять записями через административную панель.

## 🎯 Назначение и решаемые проблемы

Без информационной системы бронирование ведётся через устные договорённости или бумажные журналы, что приводит к двойным броням и отсутствию истории. 

**RoomBook решает эти проблемы:**
* **Исключает накладки:** система проверяет пересечения по времени и не даёт создать две брони на одну аудиторию.
* **Прозрачность:** пользователь всегда видит статус своей заявки (На подтверждении, Подтверждено, Отменено).
* **История:** фиксируются все изменения статусов (кто и когда изменил бронь).
* **Удобство:** визуальный календарь занятости и实时 (real-time) уведомления.

## 👥 Роли пользователей

1. **Пользователь (Студент/Преподаватель):**
   * Регистрация и вход в систему.
   * Создание брони с указанием аудитории, даты, времени и назначения.
   * Просмотр только своих броней.
   * Отмена своей брони.
   * Просмотр статуса заявки.
2. **Администратор:**
   * Просмотр всех броней всех пользователей.
   * Подтверждение броней (перевод из статуса «На подтверждении» в «Подтверждено»).
   * Отмена и удаление любых броней.
   * Доступ к админ-панели со сводной статистикой и графиками.
   * *Роль администратора назначается защищённым способом в базе данных.*

## ⚙️ Основной функционал

* **Аутентификация:** Регистрация (имя, email, пароль от 6 символов) и вход по email/паролю через Supabase Auth.
* **Управление бронями:** Создание брони со статусом «На подтверждении». Валидация полей (время окончания должно быть позже начала, обязательные поля, минимум 5 символов для назначения).
* **Уведомления:** Всплывающие сообщения об успехе, ошибках валидации, конфликтах времени и смене статусов.
* **Календарь занятости:** Визуальная сетка занятости аудиторий по 30-минутным слотам.
* **Фильтрация и поиск:** Поиск по назначению/аудитории и фильтрация по статусу.
* **История:** Отслеживание изменений статусов (таблица `status_history`).


## 🗄️ Архитектура базы данных (ER-диаграмма)

База данных построена на PostgreSQL (Supabase) и состоит из 4 связанных таблиц. Связи показывают, как ключи (PK) переходят в внешние ключи (FK):

```mermaid

    profiles ||--o{ bookings : "создает (id -> user_id)"
    rooms ||--o{ bookings : "выбрана (id -> room_id)"
    bookings ||--o{ status_history : "имеет историю (id -> booking_id)"
    profiles ||--o{ status_history : "изменил (id -> changed_by)"

    profiles {
        uuid id PK
        text email
        text full_name
        text role
    }

    rooms {
        bigint id PK
        text name
        text building
        int capacity
    }

    bookings {
        bigint id PK
        uuid user_id FK
        bigint room_id FK
        date booking_date
        time start_time
        time end_time
        text purpose
        text status
        timestamp created_at
        timestamp updated_at
    }

    status_history {
        bigint id PK
        bigint booking_id FK
        uuid changed_by FK
        text old_status
        text new_status
        timestamp changed_at
    }
